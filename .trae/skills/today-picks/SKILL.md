# 今日推荐（阈值制）

操作 `g:\bet` 的现有流水线，不要重写模型逻辑。模型参数、筛选条件、结算口径以项目根目录的 `AGENTS.md` 为准。

## 出单

1. 运行（抓取约 2 分钟，建议后台写日志再读取）：

   ```
   python today_picks.py --date YYYYMMDD
   ```

   若 PATH 中没有 python，使用 `C:\Users\Administrator\anaconda3\python.exe`。

2. 默认门槛 `|p_raw−0.5| ≥ 0.12`，**达标即出，不设名额上限**。不是取前 5 名。

3. 结果表字段：开赛、联赛、对阵、状态、方向、来源（新/锁）、校准概率、原始概率、盘口、水位、EV、std、dev、强度。

4. **只增不减**：当天已出的单，后续重算跌破门槛也保留（标记 `锁`），不撤销、不替换。这是阈值制相对 top5 的核心差别。

5. 无盘口/无水位的场次照常保留，结算时标注"无法下注"，不做前置剔除。

6. 脚本自动记录，不要手工编辑：

   - `titan_data/top5_changes.json`：保留/移除/新增
   - `titan_data/top5_snapshots.json`：每次变动的完整快照
   - `titan_data/today_picks_YYYYMMDD.json`：当日最终出单

## 资金管理（阶梯加码）

初始本金 1 万、100 元/场起步，按累计净利润升档：

| 累计净利 | 单注 |
|---|---|
| < 2000 | 100 |
| 2000 ~ 3999 | 150 |
| 4000 ~ 5999 | 200 |
| 6000 ~ 9999 | 300 |
| ≥ 10000 | 400 |

- 只升不降，回撤期不降档。
- 升档只看累计净利，不看当天输赢。
- 汇报时同时给出"按 100 元/场"和"按当前档位"两种盈亏。

## 结算

- `python temp/settle_picks.py YYYYMMDD`
- 已开赛的比赛必须用比赛 id 查比分并结算，不允许跳过。
- 无盘口的注标注"无法下注"，不计入汇总。
- 结算后更新累计净利，判断是否需要升档。

## 复盘

- 读 `titan_data/today_picks_YYYYMMDD.json` 取当日最终出单。
- 读 `titan_data/top5_changes.json` 看当天是否有增减。
- 跨日复盘：按天汇总注数、赢注数、盈亏 U、ROI；同时给累计资金曲线。

## 固定口径

- 业务日为 12:00 至次日 12:00，`listings.json` 的 `date` 已符合，不需要二次转换。
- 盘口正数=主队让球，负数=主队受让。
- 结算单位：赢盘 +1、赢半 +0.5、走盘 0、输半 −0.5、输盘 −1；押客队取反。
- 比分接口及字段位置见 `AGENTS.md`。
- 门槛变更必须跑 `temp/tune_live_gate.py` 重扫，禁止凭印象调参。

## 汇报要求

给出结果表、已开赛的结算情况、当日盈亏与资金档位。结论直接说值不值得打，不要堆无关数据。
